## Goal

Land the module-header convention in `coding-standards.md` and rewrite the
twelve history-led headers in `packages/core/src` to it, so a human reader
meets what the module does first and its history last. Comment-only work:
no code, signature, behavior, or test change.

## In scope

- One new `Module headers` rule in `coding-standards.md` under the existing
  `Comments` section, with this shape (max ~8 lines, no banners or
  dividers beyond it):
  `// <package> - <what lives here>, one line.` then `// Owns: ...`,
  optional `// Surprising: ...`, then a single trailing
  `// History: <items>; see docs/SESSION_HANDOFF.md.`
- Header rewrites for the twelve surveyed files: `curriculum.ts`,
  `evaluation-job.ts`, `evaluation-model.ts`, `evaluation-pipeline.ts`,
  `hints.ts`, `interview-message.ts`, `profile.ts`, `recommendation.ts`,
  `selection.ts`, `skill-update.ts`, `skill.ts`, `submit-verdict.ts`.
- Opportunistic function-comment fixes confined to those files: delete
  comments that restate the signature, keep why-comments. No new
  per-function narration beyond that.

## Out of scope

- `apps/api/src`, `apps/web/src`, `packages/store/src` headers (4b/4c/4d).
- Test files, generated files, frozen/archival docs, plan files.
- Any production code change: bodies, signatures, names, and string
  literals stay byte-identical outside comments.
- The stale Monorepo-map paths in coding-standards.md (open finding F-15);
  touch only the Comments section.
